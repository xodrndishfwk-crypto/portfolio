# 실행 기록 해석

[확실] `evidence/verification.json`은 기존 작업 폴더에 있던 기록을 복사한 것입니다. mode=replay, code_cells_executed=43, all_passed=true로 기록되어 있습니다. 파일만으로 실행 주체나 제출 시점의 진위를 독립적으로 인증하지는 않습니다.

| 범위 | 기존 기록 |
|---|---|
| Step0~3 | 기존 전처리·질량·라벨·기준 접근성 입력 재사용 |
| Step4 | α 후보 탐색·중력 재계산·AFT 학습 및 train/validation/test 평가 |
| Step5 | 잔여시간·위험·우선순위·가상 시나리오 재계산 |
| Step6 | 대응 분류·시설 분해·조건부 서비스 연결·거점 시나리오·PDF 재계산 |
| rebuild 전체 | 미실행, 포함 코드의 문법 검사만 기록 |
| 선택형 지도 출력 | 해당 실행에서 미수행 |
| 미래 실제 고립 결과 검증 | 미수행 |
| LLM/API 에이전트 | 호출 없음, 규칙 기반 설계·시연 |

[확실] `historical_alpha_checks.json`에는 원본 해시 보존·α 양수·그룹 평균 1·공간 셀 분할 중복 없음·라벨 보존 등의 점검이 기록되어 있습니다. `not_future_period_test=true`이므로 미래 기간 검증이라고 주장하면 안 됩니다.

[확실] 공개용 사본은 출력 제거와 개인 경로 대체를 거쳤습니다. 이번에는 Python 문법과 노트북 JSON 구조, 포함 파일 해시를 확인했습니다. 원자료 기반 분석 결과를 다시 계산하지 않았습니다. 전체 상세 결과를 공개하지 않으므로 검증 요약만으로 성능을 독립 재현할 수 없습니다.

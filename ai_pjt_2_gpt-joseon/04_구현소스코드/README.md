# ㅈㅍㅌ 조선 GPT-Joseon

## 1. 프로젝트 개요 및 실행 방법

### 프로젝트 개요

**GPT-Joseon은 조선시대 역사 질문에 관련 기록을 찾아 근거와 함께 답하는 RAG 기반 지식 서비스입니다.** 사용자가 사건이나 인물을 자유롭게 질문하면 관련 왕대와 시기를 파악하고, 실록 한문 전사본과 공개 역사 해설을 검색해 답변을 생성합니다.

훈장님 캐릭터가 사건의 시점과 배경을 쉽게 설명하며, 사용자는 답변의 인용 번호를 눌러 실제 근거와 원출처를 확인할 수 있습니다. 한문 전사본은 한글 AI 번역과 함께 읽을 수 있습니다. 왕·재위 연도 선택은 보조 탐색 기능이며, 선택하지 않아도 질문할 수 있습니다.

**질문 예시**

- 임진왜란 때 선조는 언제 의주로 피란 갔어?
- 태종이 낙마한 일을 사관에게 알리지 말라고 했어?
- 이괄의 난은 언제, 어떤 배경에서 일어났어?
- 이괄은 패전한 뒤 어떻게 됐어?

### 현재 화면과 대화 표현

- 수직 기와와 검은 나무 편액에 월인석보체 제목을 표시합니다.
- 질문은 푸른 두루마리, 답변은 붉은 두루마리이며 내용 길이에 따라 높이가 바뀝니다.
- 새 답변이 완성되면 펼침 → 붓쓰기 → ㅈㅌ / ㅍ인 도장 순서로 재생합니다. 모델 토큰 스트리밍이나 손글씨 생성 모델은 아닙니다.
- 왼쪽에는 대나무와 두루미, 오른쪽에는 수묵 소나무·까치와 푸른 호랑이를 배치했습니다. 눈 깜빡임, 소나무 상부 잎 흔들림, 까치 부리 동작은 시각 연출이며 소리는 없습니다.
- #e2c9a3와 #af8352 계열의 옅은 산수화는 기존 장식 뒤에 놓입니다. 고정 장식은 입력을 막지 않으며 화면 폭 1340px 이하에서는 숨깁니다.
- 동작 줄이기 설정을 따르며 저장된 대화는 즉시 읽을 수 있습니다.

### 설치 및 환경 설정

소스코드가 있는 폴더에서 실행합니다. 제출용 묶음을 받은 경우 `04_구현소스코드.zip`을 먼저 풀고, 생성된 `04_구현소스코드` 폴더로 이동합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-ui.txt
```

`.env.example`을 참고해 프로젝트 루트에 `.env`를 작성합니다. 기존 `.env`가 있다면 덮어쓰지 않고 사용합니다.

```dotenv
GMS_KEY=본인의_GMS_키
GMS_MODEL=gpt-6.1-sol
GMS_EMBEDDING_MODEL=text-embedding-3-small
```

외부 환경 파일을 사용하는 경우에는 `GMS_ENV_FILE` 환경변수에 해당 파일 경로를 지정합니다. 외부 출처의 요청 식별에 사용하는 `HISTORY_SOURCE_CONTACT`에는 실제 사용할 연락처를 설정합니다. API 키와 개인 환경 파일은 소스코드에 포함하지 않습니다.

### 최초 색인 및 실행

동봉된 왕력 데이터를 먼저 색인합니다. 임베딩과 실제 질문 처리는 GMS를 호출하므로 접근 권한과 크레딧이 필요합니다.

```powershell
.\.venv\Scripts\python.exe -m scripts.index_timeline
.\.venv\Scripts\python.exe -m uvicorn api:app --host 127.0.0.1 --port 8502
```

브라우저에서 **http://127.0.0.1:8502/** 에 접속합니다. Vue 런타임은 소스에 포함되어 있어 별도 Node 빌드가 필요하지 않습니다. 서버를 실행한 터미널을 종료하면 접속할 수 없습니다.

기존 Streamlit 화면은 다음 명령으로 실행합니다.

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address 127.0.0.1 --server.port 8501
```

Streamlit 접속 주소는 **http://127.0.0.1:8501/** 입니다. 두 화면은 같은 Python RAG 모듈을 사용합니다.

### 사용 방법

1. 채팅창에 역사 질문을 입력합니다. 필요한 경우 왼쪽에서 왕과 재위 연도를 선택합니다.
2. 검색·수집·답변 생성 진행 상태를 확인합니다.
3. 훈장님의 답변과 인용 번호를 확인합니다.
4. 인용 번호 또는 `기록 살펴보기`를 눌러 문서 제목, 원출처와 본문을 확인합니다.
5. 한문 근거는 AI 한글 번역으로 읽고, `한문 원문 함께 보기`를 펼쳐 대조합니다.
6. 후속 질문을 입력하거나 제안된 질문으로 대화를 이어갑니다.

대화는 브라우저에 저장되며 자유 대화와 선택 연도별 대화가 구분됩니다. 다른 브라우저와 자동으로 동기화되지는 않습니다.

### 선택 사항 임시 외부 시연

로컬 작업 주소는 http://127.0.0.1:8502/ 입니다. Cloudflare Quick Tunnel을 사용할 때만 공개 호스트명을 HISTORY_PUBLIC_HOSTS에 설정하고 공유용 서버를 127.0.0.1:8503에서 실행합니다. 기본 설정은 localhost 전용입니다. API 키는 .env 또는 GMS_ENV_FILE에서만 읽으며 정적 폴더에 넣지 않습니다.

링크는 PC·서버·터널이 켜진 동안만 동작하고 재시작 시 바뀔 수 있습니다. 로그인과 사용자별 할당량은 없으며 방문자의 질문은 현재 API 사용량을 소모합니다. 한 번에 한 질문만 처리해 동시 요청에는 대기 안내가 나올 수 있습니다. 정식 운영 서버 배포와는 구분합니다.

## 2. 전체 기능 설명

명세서의 **필수 기능 F2001~F2012**와 **심화 기능 F2013~F2016**을 기준으로 구분합니다. 아래 설명은 현재 구현을 기준으로 하며, 미완료 또는 추가 검증이 필요한 범위도 함께 표시합니다.

### 심화 기능

### 현재 확인 범위

자동 테스트 **51개 통과**와 대표 질문의 실제 답변·인용·번역 화면을 확인했습니다. 모든 연도 자체 문서의 연결, 전체 역사 질문의 정확도, MMR의 답변 품질 효과, Vue에서 색인 0건 상태의 전용 안내는 추가 검증이 필요합니다. 왕력 표로 직접 답하는 좁은 연도 대응 질문은 일반 RAG 검색과 별도의 경로로 처리합니다.

## 3. 데이터 준비 및 색인 절차 요약

### 항목 데이터 준비

항목 데이터는 `resources/royal_years.json`에 있습니다.

- **27개 왕대, 542개 왕력 연도 항목**을 포함합니다.
- 서기 **1392~1910년의 519개 연도**를 다룹니다. 왕이 바뀐 해에는 여러 왕력 항목이 존재합니다.
- 493개 항목은 ITKC 공식 목차에서 추출했습니다.
- 고종·순종 49개 항목은 공식 자료의 왕력 표기를 확인해 내부 연도표로 구성했습니다.
- 이 수치는 항목 메타데이터 수이며, 실록 기사나 본문 542건을 확보했다는 뜻이 아닙니다.

동봉 데이터를 사용하면 재수집 없이 색인할 수 있습니다. 목록을 다시 준비하려면 다음 순서로 실행합니다.

```powershell
.\.venv\Scripts\python.exe -m scripts.prepare_timeline
.\.venv\Scripts\python.exe -m scripts.index_timeline
```

### 외부 문서 수집과 본문 색인

질문을 입력하면 다음 흐름으로 필요한 외부 문서를 수집·색인합니다.

```text
사용자 질문과 대화 맥락
  → 검색어 추출 QUERY
  → 공식 사료 후보 및 공개 해설 검색
  → 관련 후보 선별 SELECT
  → 문서별 이용 조건 확인과 본문 수집
  → 청킹 및 임베딩
  → 본문 컬렉션 저장
  → 두 컬렉션 검색과 병합
  → 근거 기반 답변 생성 ANSWER
  → 인용 번호와 실제 인용문 검증
```

이미 확보한 검색·본문·번역 결과는 캐시를 재사용합니다. 본문이나 청킹 설정이 같으면 재색인을 건너뛰며, 같은 문서를 여러 항목에 연결할 때는 항목별 관계 ID를 사용합니다.

### 컬렉션과 주요 설정

| 구분 | 구성 |
| --- | --- |
| 항목 컬렉션 | `royal_year_meta_v2_<임베딩 모델 해시>`: 왕력 항목당 한 청크 |
| 본문 컬렉션 | `external_docs_<임베딩 모델 해시>`: 사료·해설 본문의 분할 청크 |
| 청크 크기 | 1,000자 |
| 중복 길이 | 200자 |
| 본문 Top-k | 7 |
| MMR 후보 수 | `fetch_k=24` |
| MMR 가중치 | `lambda=0.65` |
| 실행 설정 | `config.json` |
| 로컬 저장 | `data/records.sqlite3`, `data/chroma/` |

Top-k는 본문 검색의 기본 예산이며, 항목 메타데이터 등이 별도로 추가되어 최종 전체 근거 수가 반드시 7인 것은 아닙니다. 별도 프로세스로 색인을 변경했다면 실행 중인 서버를 재시작합니다.

제출용 소스에는 개인 실행 DB와 수집 캐시를 포함하지 않았습니다. 새 환경에서는 메타데이터를 색인한 뒤 질문 과정에서 본문을 수집합니다.

### 검증 명령

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v

```

자동 테스트에는 모의 모델과 합성 문서를 사용한 검사가 포함됩니다. 테스트 51개 통과가 역사 질문 51개의 정답 검증을 의미하지는 않습니다.

### 현재 실행 검증

2026년 10월 23일 기준 왕력 542항목과 메타데이터 542청크, 본문 469청크를 확인했습니다. 실제 메타데이터를 연속 두 번 재색인해 추가 청크가 각각 0건임을 확인했습니다. SQLite에는 검색 후보 699건 중 본문 68건이 저장되어 있으며 미확보 후보를 전부 수집 실패로 해석하지 않습니다. 건수는 질문에 따라 변할 수 있습니다.

자동 테스트 51개와 pip check를 다시 통과했습니다. 태종 낙마 질문은 실제 공개 앱에서 약 42.8초에 완료했습니다. 단일 관찰값이며 평균 성능이나 최대 시간을 보장하지 않습니다. 이번 재검토에서는 기존 엑셀을 변경하지 않았고 동료 상호 점검은 별도 후속 작업으로 제외했습니다.

### 설정 변경 실험과 확인 범위

같은 운영 코퍼스에서 “태종이 낙마한 일을 사관에게 알리지 말라고 했어?”를 `Index.retrieve`로 검색했습니다. 답변 생성 전의 병합 목록 비교이며, 사료 우선 검색과 메타데이터가 별도 추가되므로 최종 개수는 Top-k와 다릅니다.

| 방식 | 본문 Top-k | 병합 청크 | 고유 문서 | 검색 관찰 시간 |
| --- | --- | --- | --- | --- |
| similarity | 3 | 9 | 9 | 0.97초 |
| similarity | 7 | 10 | 9 | 1.39초 |
| mmr | 7 | 13 | 9 | 3.80초 |

세 경우 모두 태종 낙마 원문이 남았지만 질문과 무관한 메타데이터도 섞였습니다. 최종 답변에서 실제로 인용한 근거만 보여주는 이유입니다. 위 시간은 단일 검색 관찰이며 질문 전체 처리 시간과 다릅니다.

저장된 허용 본문 ‘일제강점기’ 47,531자를 분리된 Chroma에 실제 색인했습니다. 청크 크기/중복 길이 `600/120`, `1000/0`, `1000/200`, `1400/280`의 결과는 각각 **133, 71, 73, 52청크**였습니다. 같은 설정으로 반복할 때 신규 청크는 모두 0건입니다. 이 실험은 모의 임베딩으로 분할·저장·중복 방지만 확인했으며 검색 품질 평가는 아닙니다.

공식 검색 ‘낙마’의 최초 요청은 약 81.36초 뒤 실패했습니다. 반복 호출에서는 실패 캐시로 네트워크 호출이 0회였습니다. 성공 수집 캐시 또는 질문 전체의 무재수집을 입증한 사례로 사용하지 않습니다.

원시 증거는 소스 묶음의 `evidence/retrieval_comparison.json`, `evidence/chunk_index_comparison.json`, `evidence/cache_comparison.json`에 있습니다. 왕력 전체의 외부 문서 연결과 Vue의 빈 색인·키 누락·무인용 안내 화면은 추가 확인이 필요합니다.

### 원문과 번역의 구분

- **한문 원문 전사본**: 위키문헌에 수록된 텍스트입니다. 국편 공식 판본과의 교감은 미완료입니다.
- **AI 번역**: 확보한 한문을 모델이 현대 한국어로 옮긴 결과입니다. 기존 국역과 다르며 오류가 있을 수 있어 원문을 함께 제공합니다.
- **AI 해설**: 확보한 근거를 바탕으로 사건의 배경이나 어려운 표현을 풀어 쓴 설명입니다.

문서별 `rights_status`와 `rights_basis`를 확인한 뒤 본문 저장과 외부 모델 전송을 수행합니다. 원출처가 같아도 이미지나 제3자 저작물까지 같은 조건으로 사용할 수 있다고 간주하지 않습니다.

화면 글꼴의 출처와 라이선스는 `frontend/fonts/NOTICE.txt`와 동봉된 라이선스 파일에 있습니다. Vue 런타임의 MIT 라이선스는 `frontend/vendor/`에 포함했습니다. 훈장님 캐릭터, 종이 질감, 수묵 장식과 산수화는 프로젝트용 AI 생성 자산입니다. 우측 푸른 호랑이는 요청한 KPop Demon Hunters의 Derpy에서 착안한 시안이며 공식 제휴물이나 독점 캐릭터로 주장하지 않습니다. 사용자 제공 실록 사진과 대외비 PDF는 재배포하지 않습니다. 현재 편액은 월인석보체로 만든 제목 이미지를 사용하며 폰트 바이너리는 서버나 제출물에 넣지 않습니다.

## 5. 심화 기능 적용 요약

### F2013 프론트엔드 직접 구현

기존 Streamlit RAG 모듈에 FastAPI 서버와 Vue 화면을 연결했습니다. 질문 요청은 `POST /api/questions`, 진행 및 결과 조회는 `GET /api/jobs/{job_id}`로 나눴습니다. 답변과 근거는 자료 패널에서 확인하고 검색 설정은 별도 실험실에서 조정합니다. API 키와 모델 호출은 Python 서버에서 관리합니다.

### F2014 MMR 검색 적용

검색 방식으로 `similarity`와 `mmr`을 선택할 수 있습니다. MMR은 후보를 넓게 검색한 뒤 다양성을 고려해 청크를 고릅니다. 다만 이후 사료 우선 병합 등도 적용되므로, 최종 근거 전체가 MMR 결과만으로 구성되는 것은 아닙니다. 실제 같은 질문의 근거 목록 차이는 3절의 표와 동봉 증거에 기록했습니다. 고유 문서 수는 모두 9개로 동일하므로 다양성이나 답변 품질의 우위를 주장하지 않습니다.

### F2015 RAG 사용 전후 품질 비교

이번 제출에서 선택하지 않았습니다. 이 심화를 선택할 때는 대표 질문 5개 이상의 RAG 미사용 답변과 사용 답변을 확보하고, 사실 정확성·근거 제시·불확실성 표현을 비교해야 합니다. 현재 자동 테스트나 일부 실제 질의 결과로 이 요구사항을 완료 처리하지 않습니다. F2015는 완료 심화로 선택하지 않았습니다.

### F2016 여러 문서 출처 결합

한문 사료 전사본과 역사 해설을 함께 색인합니다. 각 청크에 출처 유형·문서 제목·원출처·이용 조건을 남겨 사용자가 자료의 성격을 구분하도록 했습니다. 한문 전사본은 날짜별 구간을 수집하고, 웹 해설은 관련 항목의 본문을 수집한 뒤 공통 청킹·검색 흐름으로 연결합니다.
